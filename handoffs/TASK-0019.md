## Objective
Password sign-in for active accounts, TOTP two-factor authentication with recovery codes, throttling, and an audit trail without credentials (docs/07 Authentication, docs/02 §3.2). Laravel Fortify 1.41.0 with everything off except two-factor; Inertia pages for login, challenge, password confirmation and security settings.

## Review focus
1. Authentication: can a suspended, deactivated or unknown account sign in, or be told apart from a wrong password (message, status, timing)? Session fixation, remember-me, logout.
2. Two-factor: can it be bypassed (challenge skipped, code replay, recovery code reuse, enabling/disabling without password confirmation)? Secret and recovery-code storage and exposure (props, JSON endpoints, logs, audit).
3. Throttling: per account and per IP, two-factor limiter keyed on the pending login; can an attacker lock out a victim indefinitely, and is that acceptable?
4. Audit: does any listener record a password, code, secret or the submitted email of an unknown account?
5. Fortify surface: are disabled features really unreachable; any route left open that should require auth?
6. Dependencies: the transitive pins (ADR-0003) and the unused passkey libraries pulled in by Fortify.
