## Objective
First story of Sprint 1.3 (docs/11 P1-30, docs/04 §2, docs/02 §3.4, docs/03 Sources). Analysts propose sources; nothing can use a source until a policy review approves it (P1-31).
- **New module `Sources`:**
  - `sources` table: grant class `no_delete`, CHECKs, and a rollback that refuses while sources exist;
  - `Source` model: classified, unscoped, shown through `AccessScope`;
  - `SourceService::propose`, `SourceController` (list, detail, store), the proposal request, Vue pages.
- **Differences from the ERD:**
  - `proposed_by` added, so P1-31 can refuse the proposer as approver;
  - `current_policy_id` deferred to P1-31 together with `source_policies`.
- **Collection flag:** `Modules\Platform\Support\Features` reads `config/features.php` (`FEATURE_COLLECTION`). Only `true` switches it on, and an unknown flag name throws. While the flag is off, every method except `manual` is refused, by both the request and the service. Pennant (docs/10) is not installed; the class is the seam to swap it in later.
- **Base URL rules:**
  - an http(s) address (`Platform\Support\WebAddress::isValid`, moved from `CompetitorService::isWebAddress`, which now delegates to it);
  - no user name or password;
  - a domain name: no IP literals, no single-label names;
  - `host` is stored as the lower-case punycode domain;
  - the address is never fetched.
- **Owner:**
  - defaults to the proposer;
  - otherwise an active `source.propose` holder, checked under a shared lock on the user row (`lockedActiveHolder`);
  - the owner must be able to see the source: new `UserDirectory::account(int)` returns the account only for `AccessScope` checks.
- **Audit:** `source.proposed` records codes only (type, method, classification).
- **Navigation:** a Sources link for `source.view` holders.

## Review focus
1. **Authorization and visibility:**
   - route middleware plus the service check;
   - hidden sources are 404 and list filtering goes through `AccessScope`;
   - nobody can classify a source above what they can see;
   - the owner rule;
   - does `UserDirectory::account()` widen what other modules can do with user records in a way that matters?
2. **Collection flag:**
   - Can anything create a non-manual source while the flag is off?
   - Is "only `true` counts" safe with `env()` parsing, config caching and string values?
3. **Base URL handling:**
   - credential leakage (userinfo, and secrets in query strings, which can't be detected);
   - bypasses of the domain rule (trailing dots, IDNA edge cases, numeric hosts, IPv6, percent-encoding);
   - XSS through the stored URL on the pages;
   - whether the CHECK constraints match the application rules.
4. **Schema:**
   - CHECKs, collations (reliability case, host case), indexes, foreign keys and grant class;
   - the refusing rollback;
   - the ERD differences;
   - anything P1-31 (policies, lifecycle, proposer ≠ approver) will need that is missing now.
5. **Tests:** gaps in `SourceTest` and `Sources.test.ts`, including the authorization matrix use.
