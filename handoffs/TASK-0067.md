## Objective
PO decision 2026-11-03.

**Background:** `RegistryConcurrencyTest` failed twice, each time in the test process's setup, with "already taken" for a name or code that could not exist yet: `CategoryService::create` once, and `CurrencyService::create` with the message kept. Every Registry service turned *any* unique violation in its transaction into that message, so the real key was hidden.

**Changes:**
- **New helper:** `Modules\Platform\Database\UniqueViolation::on($e, $table, $index)` reads the index from MySQL's message ("Duplicate entry '…' for key 'table.index'", or the bare index on older servers).
- **Every catch of `UniqueConstraintViolationException` now checks its index; anything else is rethrown:**
  - **Registry services (20 sites):** each name/code key; `currencies.PRIMARY`.
  - **`CompetitorService`:** retries the slug only on `competitors_slug_unique`.
  - **`CompetitorTagService`:** treats only `taggables.PRIMARY` as already tagged.
  - **`AuditCheckpointer`:** only its two checkpoint keys mean "a concurrent run closed this range".
  - **`OutboxRelay`:** only `outbox_receipts_outbox_event_id_handler_unique` means "a concurrent delivery won". A duplicate raised by the handler's own writes used to be swallowed, so a failed delivery looked handled. It now fails the delivery, which is retried.
- **Tests:**
  - `UniqueViolationTest`: the expected duplicates still give validation errors; a forced duplicate audit-row ULID inside a create surfaces as itself; the helper reads the index.
  - `OutboxTest::test_a_duplicate_raised_by_the_handler_itself_fails_the_delivery`.

## Review focus
1. **Index mapping:** is each catch mapped to the right index? Check against the migrations; the index names were read from the database.
2. **Message parsing:** is reading the index from the message robust on MySQL 8.4 (format, quoting, a value containing `for key '`)?
3. **Rethrowing:**
   - does rethrowing change transaction handling (`DB::transaction` attempts, savepoints)?
   - is any caller relying on the old catch-all?
   - is anything left in Registry or Platform that still catches broadly?
4. **Outbox:** the change of semantics, and the retry/dead-letter path for a handler that always raises a duplicate.
5. **Tests:** gaps. Please mark anything that is not a merge blocker as such.
