## Objective
Confirm that the TASK-0096 findings are fixed (`handoffs/TASK-0096-review.md`, the disposition section), and that the fixes introduce nothing new. The review said "no".

## Fixes
1. **High, a forged supplement could be signed.**
   - `AuditAnchor::anchorPending` exports only `revision = 1`.
   - `reanchor(from, lateIds, reason)` (`audit:reanchor {from} --late=ID,ID --reason=`):
     - reads the range's latest **signed manifest from the bucket** (`AuditVerifier::signedRange`);
     - requires every row to match its hash, every late ID to be a row of the range, and the rows *without* the late IDs to equal the manifest's count and Merkle root;
     - then inserts revision + 1 (with `supplements_id` pointing at the signed revision's row), audits `audit.reanchored` with `late_ids` and the reason in the same transaction, and exports it;
     - resumes the export if that revision already exists unexported with the same count and root.
   - A supplementary row without a manifest is reported as `unsigned_supplement` (critical).
2. **High, deleted export records were undetected.**
   - For each valid manifest, verification compares the `audit_anchors` row (object key, key ID, signature). A missing or different row is `anchor_record_mismatch` (high).
   - On export, identical bytes already at the key are not written again: the anchor row is recorded again and a warning is logged.
3. **Medium, fake checkpoints.** A first revision is exported only if its `from` is the last exported checkpoint's `to` + 1. Otherwise the run stops with an exception.
4. **Medium, the verifier needed the seed.** `AuditSigner::trustedKeys` includes the current key only when the seed is configured. The verifier requires at least one trusted key, never the seed.
5. **Medium, an auditor outage was not observable.**
   - New `audit:freshness` (`CheckAuditFreshness`), scheduled every 15 minutes in the ordinary scheduler, which holds no key. It reads the database only.
   - It logs critically and exits 1 when audit rows older than the lag window plus 30 minutes are past the last exported checkpoint.
6. **Low, semantic checks.** Before the signature, a manifest must have:
   - generation and revision ≥ 1;
   - 1 ≤ from ≤ to;
   - 0 ≤ count ≤ to − from + 1;
   - a 64-hex root and a 16-hex key ID;
   - `Y-m-d H:i:s.u` times.

Tests added to `AuditAnchorTest`:
- a forged supplement is never signed;
- wrong, unnamed or out-of-range late IDs are refused;
- a checkpoint that does not continue the signed ranges is not signed;
- a changed or deleted export record is reported and recorded again visibly;
- verification works from public keys only;
- a signed manifest with values out of range is rejected;
- the freshness watch;
- the schedule holds only `audit:freshness`.

Docs: docs/02, docs/10 (alerts; runbooks for `--late` and `anchor_record_mismatch`), ADR-0006.

## Questions
