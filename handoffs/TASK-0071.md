## Objective
Verify the fixes recorded in `handoffs/TASK-0070-review.md`:
1. **Lost dispatch (#1):** new `evidence:dispatch-scans` (`modules/Evidence/src/Console/DispatchPendingScans.php`), scheduled every five minutes in `EvidenceServiceProvider`.
   - It queues the scan again for assets `quarantined`/`pending` whose `updated_at` is older than `evidence.scan_stale_minutes` (15).
   - `ScanEvidenceJob`'s unique lock keeps a scan that is still queued or running from being doubled.
   - `error` assets (retries exhausted) are left for the operator.
   - The misleading comment in `EvidenceUploadService` is corrected.
2. **Duplicate locked versions (#2):** `EvidenceScanService::store()` holds a MySQL named lock per hash (`GET_LOCK`, `evidence.blob_lock_seconds` = 120) around the blob lookup, the object write and the insert.
   - The lock is released in `finally`.
   - If the lock is not acquired, the scan fails and is retried with nothing written.
3. **Version ID (#3):** `LockedObjects::write()` throws when the S3 store returns no version ID. The empty ACL is kept, deliberately; the reason is in the review record.
4. **Non-S3 fallback (#4):** `LockedObjects` refuses any disk other than the S3 adapter outside the `testing` environment. Orphan objects are left to P1-38.
5. **`scanned_at` (#5):** declined; P1-32a's state CHECK requires it.

3. Does the version-ID check or the testing-only fallback break anything the branch relied on before?
