## Acceptance criteria
1. **The scan job:** `ScanEvidenceJob` on a new `evidence` queue.
   - Add the queue to Horizon (`config/horizon.php`).
   - Unique per asset; 3 tries with backoff of 30, 120 and 600 s.
   - Dispatched after the upload's transaction commits.
2. **The ClamAV client:** an in-house clamd `INSTREAM` client in `Modules\Platform` (ADR-0003: no package).
   - TCP to the `clamav` service, configurable host and port, connect and read timeouts, chunked stream.
   - Any error, timeout or unexpected reply means scan status `error` (retryable), never clean.
3. **Checks on the stored quarantine bytes:** SHA-256, and the type detected again from the bytes.
4. **Clean and matching files:**
   - copied to the private `evidence` bucket (a new `s3-private` disk; versioned; object lock in governance mode) at `sha256/<2>/<2>/<hash>`;
   - recorded in `evidence_blobs` (a new migration with the specified columns, DATETIME(6), a grant class, and `evidence_blob_id` on the asset), created by `INSERT … ON DUPLICATE KEY UPDATE id = LAST_INSERT_ID(id)` and a reload;
   - the asset becomes `available`, `scan_status` `clean`, `quarantine_key` NULL (the database requires it);
   - the quarantine object is deleted.
5. **Infected or mismatched files:** the asset becomes `rejected` (`infected`, or `clean` with the type refused), and the quarantine object is deleted. A failed delete is logged as `evidence.quarantine_orphan`, as in P1-32a.
6. **Records:**
   - custody events `scanned` and `rejected` (actor `system`);
   - audit with codes only;
   - the asset page shows the result.
7. **Monotonic results:** pending → clean, infected or error; error → pending to retry. A terminal result is never overwritten, and a duplicate or retried job changes nothing.
8. **Tests** (CI has no ClamAV and no object store):
   - a fake clamd, or a client double;
   - `Storage::fake`;
   - the EICAR test string rejected;
   - a type mismatch rejected;
   - a clean file promoted, with the blob reused for the same bytes;
   - a scanner error retried;
   - a duplicate job harmless;
   - the database rules proven by direct SQL;
   - the grant class tested.

   Plus one manual smoke run against the local ClamAV and SeaweedFS, recorded with its result.
9. **Docs:** `docs/02` implementation note, `docs/03`, `docs/10` (the queue and its worker), `docs/11` status, the `docs/12` ledger, the session history, and ADR-0003 if anything is pinned.
