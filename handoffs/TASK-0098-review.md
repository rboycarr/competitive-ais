## 2. New findings

None identified.

The repair path does not appear abusable for an overlapping forged checkpoint:

- The existing locked object must contain the exact deterministic manifest and valid signature.
- The checkpoint must reproduce the same generation, range, revision, count, root, timestamps, and key ID.
- The schema uniquely constrains `(generation, from_audit_id, revision)`, so a second checkpoint cannot be inserted with the same manifest identity.
- If checkpoint data is changed, the generated bytes differ and `LockedObjects::write()` is reached; the existing locked object should reject replacement.

The bypass therefore applies to restoring a missing `audit_anchors` row for the same checkpoint, which is the intended repair behavior.
