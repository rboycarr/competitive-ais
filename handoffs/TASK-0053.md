## Objective
PO decision 2026-11-02: install Laravel Pennant now, replacing P1-30's configuration flag (`config/features.php`, `FEATURE_COLLECTION`), so a flag can change at run time (docs/01, docs/10).
- **Dependency:** `laravel/pennant` pinned at `1.26.0` (released 2026-08-13, MIT, supports Laravel 13; Composer reported no advisories). The lock file gained only this package.
- **Store:** the `features` table (Platform migration). It has Pennant's own columns, plus `features_value_check` (`JSON_VALID(value)`).
  - Grant class `mutable`, because Pennant stores the default on a flag's first read.
  - `config/pennant.php` fixes the store to `database`, with no environment variable.
- **`Modules\Platform\Support\Features`** is the only reader:
  - flags are global (`globally()`) and default to `false`;
  - only a stored `true` is on (Pennant's own `active()` counts everything but `false`);
  - an unknown flag throws.
- **`switch()`** works in one transaction:
  - it forgets the cached value, reads the stored one, does nothing if the state is unchanged, sets the new state, and audits `feature.switched` (flag, enabled);
  - if anything fails, it forgets the cache again, because Pennant caches the new value before the commit.
- **Commands:**
  - `feature:status`;
  - `feature:switch <flag> on|off`, which acts as the system and asks for confirmation in production unless given `--force`.
- **Workers:** Pennant forgets its cache only after a job succeeds (`JobProcessed`). Platform also forgets it on `JobProcessing`, so a job never inherits a value cached before an earlier failed job.
- **Guard:** a code rule allows only Platform's `Features` class and its service provider to reference Pennant (`Laravel\Pennant`, `Feature::`, `@feature`).
- **Removed:** `config/features.php`, and `FEATURE_COLLECTION` from `.env.example` and from the secrets scan's approved values.

## Review focus
1. **Can collection be switched on without an audited operator action?**
   - Through other code paths: the facade, Blade `@feature`, `pennant:purge`, a default resolver.
   - Through stored values other than `true`.
   - Through cache staleness in web requests or queue workers.
2. **Transaction and cache correctness of `switch()`:**
   - rollback after `activate()`;
   - concurrent switches;
   - the first-read insert inside the transaction.
3. **Schema and grants:**
   - the `features` table, its JSON check and grant class `mutable` (whether the app account should be able to write it);
   - the rollback (dropping the table switches every flag off).
4. **Dependency:** the pinned version; anything in Pennant's service provider or commands that matters here (published migrations, `pennant:purge`).
5. **Tests:** gaps in `FeaturesTest` and in the updated `SourceTest` flag test.
