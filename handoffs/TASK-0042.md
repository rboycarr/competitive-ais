## Objective
The remaining reference data for markets (docs/11 P1-23b, docs/02 §3.3 P1-23b note, docs/03 Registry; PO decisions O28 and O29).
- **Currencies** become editable by `taxonomy.manage` holders (O29). They move from grant class `read_only` to `no_delete`. `read_only` stays, now empty, and is still tested by its probe. A new CHECK holds the name normal form. `CurrencyService` keeps the code fixed, and keeps the minor units fixed while a market uses the currency.
- **`channels`** (`mutable`) have a unique name and a type. A channel is kept while retailers use it.
- **`retailers`** (`mutable`) have one fixed market and one channel. Names are unique per market. The website is optional and http(s) only.
- **`tags`** (`mutable`) have a lower-case taxonomy code and a name unique within it.
- **`taggables`** (`mutable`) keep the polymorphic shape. A generated `competitor_id` carries a foreign key to `competitors`, and the type is CHECKed. A tag in use is kept.
- **`CompetitorTagService`** (`competitor.manage`, competitor visible) tags competitors. The competitor list filters by tag and shows tags.
- **Pages:** Admin › Currencies, Channels, Retailers and Tags, plus the competitor page's Tags section.

## Review focus
1. **Grants:** is moving `currencies` from `read_only` to `no_delete` correct, and does the grant run converge on existing databases? Is an empty `read_only` class handled fail-closed? Are the classes of the four new tables right?
2. **Tag integrity and leaks:**
   - Can any write (service or direct SQL) link a tag to a missing competitor, remove a tag in use, or tag a hidden competitor?
   - Does any response reveal hidden competitors? Consider the tag filter, the tags column, the profile, the removal message and the tags page.
   - Is the generated-column foreign key sound on MySQL 8.4?
3. **Currency minor units:** is the "no market uses it" rule race-free with markets created or edited concurrently (row lock plus the foreign key's shared lock)? Is anything else keyed on the currency code?
4. **Authorization:** `taxonomy.manage` on the admin routes and services; `competitor.manage` plus visibility for tagging.
5. **Audit:** context without user input (no names or websites), no events for no-ops, and the currency events without a subject.
6. **Frontend:** text rendering, the website link (http(s) only, `rel`), and the tag options offered.
