## Objective
Verify the fixes for the five TASK-0053 findings (disposition in `handoffs/TASK-0053-review.md`):
1. `features` moved to grant class `read_only`. `Features::switch()` writes on the `migrator` connection (`Features::WRITER`), and both the command and the service refuse without it.
2. `switch()` locks the global row (`lockForUpdate`) on the migrator connection, re-reads it, then writes the change and the audit row (`AuditLogger::on('migrator')`) in that same transaction. Pennant's cache is forgotten in `finally`.
3. The migration stores the `collection` row (global scope, `false`); `switch()` refuses a flag without a row.
4. `pennant:purge` is refused by a `CommandStarting` listener in `PlatformServiceProvider`.
5. The migration's `down()` refuses while any row holds a value other than `false`.

Tests:
- `FeaturesTest` now uses `DatabaseMigrations` and covers:
  - the stored rows;
  - app writes denied (MySQL 1142), including Pennant `activate()`;
  - the JSON check;
  - the migrator requirement;
  - production confirmation;
  - audit failure;
  - parallel switches (`Concurrently`: four "on" at once; three rounds of mixed on/off);
  - the per-job cache flush;
  - the purge refusal;
  - the rollback refusal.
- `SourceTest` sets flag values in Pennant's in-memory store, because the app account cannot write the table and a migrator write is invisible inside the test transaction.
