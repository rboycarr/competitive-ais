## Objective
P1-34: "As a permitted user, I download evidence; others cannot". Acceptance: policy check → a pre-signed URL valid 60 s or less; custody `downloaded` + audit; denial test. ADR-0007 adds `Content-Disposition: attachment`.

## Changes
- **`modules/Platform/src/Storage/SignedDownloads.php`** (new)
  - Pre-signs a GetObject for the stored version, with `ResponseContentType: application/octet-stream` and an attachment `ResponseContentDisposition` (Symfony `HeaderUtils`, with an ASCII fallback name).
  - The link is signed for the disk's `download_endpoint`. A pre-signed URL signs its host, and the app's endpoint (`seaweedfs:8333`) is internal.
  - Outside `local`/`testing` the link must be https.
  - A non-S3 disk is served only in tests.
- **`modules/Evidence/src/Actions/EvidenceDownloadService.php`** (new)
  - Checks evidence.download and `EvidenceAsset::seenBy`; a hidden asset is a ModelNotFound (404).
  - Then, in one transaction under a shared lock on the asset:
    - the asset must be `available` with a blob whose `integrity_status` is `ok`;
    - the link is built;
    - custody `downloaded` and audit `evidence.downloaded` (context: `sha256` only) are written.
  - The link is returned only after the commit.
  - The validity window is `min(60, max(1, evidence.download_seconds))`.
- **Controller and route**
  - `EvidenceController::download` returns `Inertia::location($url)`: 409 + `X-Inertia-Location` for Inertia, 302 otherwise.
  - The route is POST `/evidence/{asset}/download` (CSRF), with `can:evidence.view`, `can:evidence.download` and `throttle:evidence-downloads` (30 a minute per user).
  - `show` gains `canDownload`.
- **UI:** `Show.vue` gets a download button, shown only when `canDownload`. A refusal is shown as text.
- **Config**
  - `filesystems.disks.evidence.download_endpoint` = `EVIDENCE_DOWNLOAD_ENDPOINT`.
  - `.env.example` and `scripts/ci/env-example-values.txt` get `http://localhost:9000`.
  - `evidence.download_seconds` = 60.
- **Docs:** `docs/02` (implementation note), `docs/10` (operations: the endpoint, https, proxy `Host` passthrough), `docs/11`.

## Review focus
1. **Authorization:** can anyone without evidence.download, or without visibility of the asset, get a link or leave a record? Consider route-model binding by ULID, the uploader-only visibility of quarantined assets, and the 404 versus 403 choice.
2. **The link:**
   - Is the URL bound to the stored version, attachment-only, and limited to 60 s?
   - Can the file name break the disposition header, or inject into it?
   - Is building a second S3 client with `Storage::build([...] + $config)` safe? Does it carry the credentials, path style, and nothing unintended?
3. **Integrity of the record:**
   - Is there a path that returns a link without its custody and audit rows?
   - Is there a path that writes rows for a refused download?
   - Is the shared lock adequate against a concurrent status change?
4. **CSRF and redirect:** is a POST plus `Inertia::location` sound? Could the link leak through `Referer`, logs or history (it is valid at most 60 s)?
5. **Operations:** the https rule, `EVIDENCE_DOWNLOAD_ENDPOINT` left empty, and a misconfigured proxy.
