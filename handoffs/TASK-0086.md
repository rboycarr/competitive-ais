## Objective
P1-36b: "As a security owner, evidence inherits the scopes of the claims it supports". Acceptance (docs/11):
- inherited scopes on link (all-of, monotonic: never removed by unlinking without an audited admin action);
- provenance hides inaccessible evidence (with P1-45);
- adding a scope locks the asset row first, so downloads and holds (which re-check visibility under that lock) never act on a stale view (TASK-0075 #1);
- matrix rows.

## Changes
- **`EvidenceLinking`** (`modules/Evidence/src/Contracts/EvidenceLinking.php`, `Lookup/EloquentEvidenceLinking.php`):
  - `lockLinkable` now locks the asset **for update** (was share). It then judges visibility from the scope rows read with locking reads (`seesNow`), not with a plain read that would use the transaction's earlier snapshot.
  - New `lockSeen(viewer, ids)`: locks the assets for update in ID order and returns those seen now (same rule).
  - New `inherit(actor, assetId, itemUlid, competitorIds, marketIds)`: adds the missing scopes as `origin = 'inherited'`, with a `scope_inherited` custody event (details: item ULID, added IDs) and an `evidence.scope_inherited` audit event (item ULID, counts). It never removes a scope.
- **Citing** (`IntelligenceClaimService::link`): after the duplicate check, the asset inherits the item's competitors and markets. The writer must still see the asset (`lockSeen`), or the whole change is refused.
- **Editing** (`IntelligenceItemService::update`, `inheritToCitedEvidence`): when an editable item gains a competitor or market, every asset its claims cite (withdrawn claims included) inherits it. Assets are locked after the item, in ID order. Evidence the editor saw before must stay visible to them, or the edit is refused; evidence they could not see does not block the edit.
- **Monotonic:** unlinking or removing a subject leaves every scope (the pivots stay `append_only`).
- **Lock order everywhere:** the item, then competitors (share, `lockUnarchived`), then assets (for update, ID order). Holds: asset, then blob. Downloads: asset (share).
- **Not in this story:**
  - provenance hiding: the provenance view is P1-45 (the item page already describes only evidence the viewer can see);
  - an admin action to remove an inherited scope: none exists, and the app account cannot delete scope rows.

## Review focus
1. **Visibility.**
   - Is the "locking read" check correct under REPEATABLE READ, for the link, the edit, and downloads and holds racing them?
   - Is anything still judged from a stale snapshot?
2. **Deadlocks and lock order** between linking, item edits, holds, downloads, competitor archiving and scans that reuse a blob (P1-38).
3. **Monotonicity and completeness.**
   - Can evidence end up cited by an item whose competitors or markets it lacks, through creation, product subjects, subject edits, relinking or a withdrawn claim?
   - Should inheritance also happen for subjects that exist before the first citation (it does, at citation)?
4. **Refusal rule.** Is "the writer must still see evidence they saw" right? Is letting the edit through when the editor never saw the evidence acceptable?
5. **Audit and custody.** Are the details enough for a security owner to reconstruct why a scope exists?
6. **Tests.** `EvidenceInheritanceTest` (the shared matrix over inherited-only scopes; recorded, monotonic, follows new subjects; refusal) and `IntelligenceRaceTest::test_a_waiting_link_sees_scopes_inherited_while_it_waited`. What is missing?
