## Objective
Accounts are created only by invitation: hashed, single-use tokens that expire after 72 hours, audited invitation and activation, Argon2id passwords. Also: the new Identity module (User model moved from `App\Models`), spatie/laravel-permission with the docs/07 roles seeded, and the test-suite speed-up (RefreshDatabase where real commits are not needed; configurable Argon2id cost in tests only).

## Review focus
1. Token security: generation, storage (hash only), lookup, expiry, single use, replacement; can a token leak (logs, queue, audit, page props, Referer, error pages)?
2. Account creation: race between two acceptances; email already taken; invitation for one address used for another; role and clearance taken only from the invitation.
3. Inviter limits: clearance cap, super-admin rule; anything that lets an inviter grant more than they hold.
4. Seeded roles: does the migration match the docs/07 matrix? Anything a role gets that it should not?
5. Enumeration and abuse: same response for unknown, used, revoked and expired links; rate limiting; CSRF.
6. Tests: the RefreshDatabase / DatabaseMigrations mix (`tests/TestCase.php` flag reset) and the test-only Argon2id cost: can either leak into production behaviour?
