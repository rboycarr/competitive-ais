## 4. Conventions your reviews established (check new code against them)

- **Times:** DATETIME(6) in UTC, never TIMESTAMP (`docs/02` §1). New TIMESTAMP columns fail `SchemaConventionsTest`. A conversion's rollback must not restore TIMESTAMP (TASK-0062).
- **Grant classes** (`config/database.php`):
  - `mutable`;
  - `no_delete` (retired, never deleted);
  - `append_only` (SELECT and INSERT; e.g. `audit_events`, `source_policies`, `source_status_changes`);
  - `read_only` (e.g. `features`);
  - `app_excluded`.

  Every table needs a class, or the grant run fails.
- **Migrator account:** only the Platform wiring names `migrator` (`MigratorIsolationTest`); schema commands and `feature:switch` switch to it. Governance migrations refuse to roll back while their rows exist.
- **Database-held rules:** where a rule matters for integrity, the database holds it (CHECKs, composite foreign keys), and tests prove it with direct SQL and the expected MySQL error code:
  - 3819: CHECK failed;
  - 1452: foreign key failed;
  - 1451: the row is referenced and can't change;
  - 1142: the app account lacks the privilege;
  - 1062: duplicate key;
  - 3105: a write to a generated column.

  Still deferred to P1-52: fixed fields and source status transitions, held against direct UPDATEs.
- **Services:** every write re-checks permission (`Gate`), visibility (`AccessScope`; hidden records are 404) and state under a row lock, then audits in the same transaction with **codes only** (`AuditActions` allowlists context keys and types; no free text, names or URLs). Direct callers get validation errors, not type errors (TASK-0059 #2).
- **Concurrency:** parallel-request tests use `tests/Support/Concurrently` (real processes, `DatabaseMigrations`); a test that commits rows cleans them up through the migrator in `tearDown`.
- **Flags:** read through `Modules\Platform\Support\Features`, where only `value() === true` counts. Only Platform may reference Pennant (`CodeRulesTest`).
- **URLs:** base and terms URLs are http(s) on a domain name, with no credentials, query or fragment. They are stored and shown with `rel="noopener noreferrer nofollow"`, never fetched.
- **Two-factor:** `source.approve` (and the other `MfaRequirement::PRIVILEGED_PERMISSIONS`) count only with confirmed two-factor; a user who isn't enrolled is redirected to `/user/security`.
